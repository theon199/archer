# Public document retrieval

Tavily search uses basic depth, a direct HTTPS client without environment proxy configuration, and rejects decoded responses larger than 1 MiB. Search queries are sent to Tavily; retrieved results are untrusted. Synthetic HTTP tests cover the request, citation-field extraction, and response limit. A real one-query check on November 8 succeeded with three source links and verified the isolated grant, replay, journal redaction and revoke path; see [the receipt](evidence/tavily-live-20261108.json). It did not test model selection or the browser. The owner selected Tavily search to be enabled by default; explicitly disabled permissions remain disabled.

To enter the key, run `python3 /home/sri/archer/scripts/set-tavily-key.py` in a private terminal and enter it at the hidden prompts. The script writes `/home/sri/.config/archer/tavily-api-key` with mode 0600 and refuses to overwrite an existing file. Do not paste the key into chat or put it in a command argument. The V1 service is configured to read that file, and reads it afresh for each search.

For an isolated live check, run the fixed-SQLite wrapper with `ARCHER_TAVILY_API_KEY_FILE=/home/sri/.config/archer/tavily-api-key uv run --project backend --locked --extra dev python scripts/verify-tavily-search.py --evidence /absolute/new-receipt.json` from the repository root. It sends one fixed public query (consuming a credit), uses a disposable owner/database, and records sanitized grant, result, replay, journal and revocation checks. It refuses an existing evidence path and does not record the key or results. It does not test model selection or the browser. Missing credentials fail before sending a query.

`web_fetch` is a separate read-only capability from `web_search`. It reads one public HTTPS HTML/plain-text document without requiring a search API key. It is enabled by the owner's selected defaults, account-owned, versioned and journaled through the existing registry. An authenticated provisioned owner can grant or revoke it with `PUT /api/permissions/web_fetch/fetch`, body `{"enabled":true}` or `{"enabled":false}`. Model-proposed arguments cannot grant permission. Tool arguments are exactly `{"url":"https://www.sqlite.org/wal.html"}`; unknown fields, credentials and operation metadata cannot supply authority. The browser provides version-aware owner grant/revoke controls in **Tool permissions**; see [tool permissions and browser evidence](tool-permissions.md). The original checkpoint-22 retrieval receipt remains a backend/model integration receipt, separate from checkpoint-23 browser grant verification.

A grant permits outbound GET requests to public HTTPS hosts and exposes the requested URL/path/query to that host. No application authorization header, session token, cookie or proxy environment configuration is forwarded. URLs and body text are omitted from the action journal; the account-owned tool operation and run events retain the returned evidence. Repeating an operation ID reuses its durable result; a revoked/version-stale grant is checked before cached results are returned. The journal distinguishes permission denial, running, succeeded, failed, unavailable and canceled outcomes. Public content remains untrusted evidence and cannot supply instructions, permissions or preference provenance.

## Supported boundaries

- ASCII HTTPS DNS hostnames only, port 443. Literal IPs, URL user/password, fragments, backslashes, controls/whitespace, malformed labels and selected local suffixes are rejected. International paths/hosts must already be percent-encoded/ASCII IDNA; arbitrary Unicode URLs are unsupported.
- Resolve at connection time. Reject an empty/oversized DNS answer or any non-public/unsupported answer, including mixed public/private responses. Connect to one validated numeric IP, without another hostname lookup. Preserve the original hostname for HTTP Host, TLS SNI and required certificate verification. Each retrieval uses a fresh pool with no retries or connection reuse. Private/link-local/loopback/shared/multicast/reserved addresses, transition IPv6 ranges and explicit older-Python classification gaps are excluded.
- No redirect following. Only HTTP 200 text/html or text/plain is accepted. No browser/JavaScript execution, downloads, credentials, cookies, compressed responses or proxy fallback. Some valid public sites will be unavailable under these intentionally limited formats/address rules.
- Ten-second total network deadline; four-second connect/read/write limits. At most 256 KiB body, 16 KiB response headers, 16,000 returned text characters and 300 title characters. Body overflows fail rather than return apparent success. Output truncation is explicitly marked. UTF-8 decoding replaces malformed bytes. HTML script/style/template/noscript text is removed; this is text extraction, not a browser-rendered page or proof against prompt injection.
- Cancellation exits response/pool contexts and is persisted by the existing registry as canceled. Policy errors are sanitized failures; DNS/TLS/connect/protocol/timeout failures are sanitized unavailable outcomes. No raw transport error, URL or credential is copied into the journal error.

## Reproduce the verification

Use the [fixed SQLite runtime wrapper](sqlite-runtime.md), existing uv lock and existing local model. From backend:

```sh
archer_uv run --locked --extra dev pytest tests/test_web_fetch.py -q
archer_uv run --locked --extra dev python ../scripts/verify-web-fetch.py
```

The integration verifier uses a disposable synthetic owner/database, real login/owner grants/registry/journal, actual production HTTPS transport and existing Ollama `gemma4:26b`. It does not mock DNS, sockets, content or inference. It checks public SQLite WAL document retrieval, idempotent durable result, actual local DNS refusal, journal redaction/outcomes, exact local model digest, real model selection of web_fetch to read SQLite robots.txt, grounded final output and revocation. It removes temporary data and does not stop/reconfigure model services. Public pages are live and their body/output hashes can change; this is a bounded real integration receipt, not an immutable benchmark dataset.

`docs/evidence/checkpoint-22-web-fetch.json` records **16/16 real integration checks passed** at 2026-10-24 16:48:53 UTC. Final backend regression **180 passed in 28.34s**, including 46 new retrieval cases; new native bundle cold start/restart **12/12 passed** at 16:49:37 UTC (`checkpoint-22-native-deployment.json`). Native verification uses model metadata, while the separate retrieval receipt uses actual generation. Unit tests explicitly label synthetic DNS/wire/pool/response fixtures and do not count as successful real integration. They exercise URL/special-address refusal, mixed DNS and changed DNS rejection, numeric-IP dialing, original Host/SNI with certificate verification enabled, redirect/type/encoding/header/body limits, extraction/truncation, account grants/isolation/revocation/idempotency, journal privacy, cancellation and a shortened real asyncio deadline.

Current official [HTTPcore custom backend](https://www.encode.io/httpcore/network-backends/) and [async streaming](https://www.encode.io/httpcore/async/) documentation plus the [installed 1.0.9 connection source](https://github.com/encode/httpcore/blob/1.0.9/httpcore/_async/connection.py) were checked. HTTPcore is now an explicit dependency pinned to the already installed/locked **1.0.9**; no upgrade/new provider was substituted. Older-Python IP classification differences are handled with conservative explicit exclusions as well as is_global/reserved/multicast checks.
